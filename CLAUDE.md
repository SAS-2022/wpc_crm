## Decisions (do not re-research)
- Backend: Firebase — Auth (email/password), Firestore, Realtime Database (live locations only), Storage (attachments).
- Roles stored in `users/{uid}.role`: `sales_exec` | `kam` | `sales_manager` | `gm`. Enforced in security rules via `get()` on the user doc.
- KAM owns no clients; supervises sales execs where `users.kamId == kam uid`.
- State: Riverpod. Routing: go_router (role-based redirects). Maps: google_maps_flutter (switched from flutter_map/OSM 2026-10-13 for better Saudi business coverage). Markers drawn as images by `MarkerIcons` in `core/map_controls.dart`. On web, wrap every widget drawn over a GoogleMap (buttons, cards, sheets) in `PointerInterceptor` (pointer_interceptor), or clicks also reach the map (double-click on "+" zoomed to the click point). API keys: Android `MAPS_API_KEY` in `android/local.properties`, iOS `GMSApiKey` in `ios/Runner/Info.plist`, web script tag in `web/index.html` (one restricted key per platform). The web key is restricted to port 5050: run the web app locally with `flutter run -d chrome --web-port 5050` (other ports get Maps errors). Add the hosting domain (`wpc-crm-a9247.web.app`) to the key's allowed referrers before using the deployed dashboard.
- Location: geolocator with Android foreground service + iOS "Always". Tracking only during work hours (user decision 2026-10-14, replaces 24/7): default Saturday–Thursday 08:00–18:00 Saudi time (UTC+3), editable by GM/manager at More → Work hours, stored in RTDB `settings/workHours` {days[weekday 1–7], start, end (minutes)}; logic in `tracking/work_hours.dart` (unit tested). Off duty the tracker sends nothing, removes `live_locations/{uid}`, sets `presence.onDuty=false` (live map: "Off duty") and keeps a low-power coarse stream only so iOS doesn't suspend the app. Route history is deleted after 90 days by the scheduled `cleanRouteHistory` function (03:00 Riyadh). Send location every 2 minutes to RTDB (user decision; team is 7 now, max ~11). Keep RTDB (user decision) and use it for honest live data: onDisconnect presence (online/offline), updatedAt + accuracy shown on the live map, and flag mocked GPS (geolocator `Position.isMocked`).
- Client import: Excel/CSV parsed client-side on web dashboard, match by Tax ID (VAT), else normalized name; same-VAT rows merge into one client (other names kept as `aliases`). Preview diff before commit. Contacts without coordinates are imported too (lat/lng null, grey, "No location") and appear on the map once a location is set in-app or a later import resolves their pin. Logic in `lib/features/import/` (unit tested). Second importer `/import/locations`: sheet of name (or Tax ID) + location (link, "lat, lng" text, or Latitude/Longitude columns) updates locations of existing clients only; matches name or aliases; fills missing locations unless "replace existing" is ticked. Optional "add unmatched rows as new clients" (one per name; AREA column → city; pivot header salesperson → assignedTo via odooName; category B).
- Marker colour (`features/clients/visit_rules.dart`): client `category` A/B/C (default B) + days since last visit → green/yellow/red; never visited = red. Thresholds in Firestore `settings/visitRules` (defaults A 7/14, B 14/28, C 30/45), edited by GM/manager at More → Visit frequency. Blue = on today's plan (approved, not done). Markers show the category letter. Odoo import reads an optional "Category" column; otherwise new clients get the chosen default.

## Odoo export (Contact (res.partner).xlsx, ~2,540 rows)
Columns: Company Name, Complete Name, Is a Company, Google Pin, Total Payable, Total Receivable, Currency, Account Receivable, Account Payable, Contact Address Complete, Mobile, Activities, City, Tags, Company.
- Location is only a `Google Pin` short link (maps.app.goo.gl, ~606 rows). It redirects to a URL containing `!3d<lat>!4d<lng>` (use these, not the `@` viewport). Browsers can't follow it (CORS): on phones the app follows the redirects itself (`import_service._resolveOnDevice`); only the web dashboard needs the `resolvePins` Cloud Function.
- Export also has Phone, Salesperson, Street, State, Country, Tax ID. Odoo has no exportable ID; Tax ID is the key (~60% of pinned rows have one).
- Pin formats: maps.app.goo.gl / goo.gl / share.google short links (need `resolvePins` Cloud Function in `functions/`), or full URLs with coords (parsed in app). share.google links lead to a search page and can't be resolved.
- Salesperson → app user via `users.odooName` (exact Odoo text, e.g. "Sami Mansour @ Sales"); active sales execs only (`uidBySalesperson` in `import_plan.dart`) — KAM / manager rows stay unassigned. The client list/map salesperson filter still lists anyone who owns clients. Import only fills an empty assignment. Saving a sales exec with an odooName also assigns their unassigned clients (`UsersRepository._assignOdooClients`).
- Odoo webhook / API connection: ON HOLD until management approves. Do not connect to Odoo. A webhook (Odoo automation rule → Cloud Function) is the planned live-sync path; its payload includes the record id.
- Rows with empty Company Name and Is a Company = 1 are companies; child contacts have Company Name set.

## Clients editing
Sales execs edit name/contact/address/location/notes of their own clients and add clients for themselves (`source: 'manual'`, duplicate warning by name/alias/VAT); category & assignment are KAM/manager only. Odoo import also stores Company Name (as legalName), Street, State, Country, Total Receivable/Payable, Currency, and optional "Email"/"Contact Person" columns. Odoo child contacts ("Parent, Person", Is a Company = false) attach to the parent as `contacts` [{name, phone, mobile}] instead of becoming clients. Excel gives booleans as "true"/"false".

Hidden clients (2026-10-14): KAM / sales manager / GM hide a client from its page (eye icon; for clients that belong to no salesperson). `allClientsProvider` = everything readable (client page, imports, duplicate checks, plan/route lookups); `clientsProvider` = hidden left out (lists, map, plan add sheet, statistics). Visits and plan items of hidden clients are dropped from Home stats, Reports, the Visits list and route history via `hiddenClientIdsProvider`; existing plan items stay in plans. Bulk: Clients list → checklist icon (or long-press) selects clients → Hide / Show again (`setHiddenMany`, batched). A "Hidden clients (n)" chip in the Clients list shows hidden ones; it appears only for supervisors and only when some are hidden. Imports never change `hidden`; `_assignOdooClients` skips hidden clients. No rules change needed (supervisors may update any client field).

Client transfers (2026-10-15): move clients between sales execs from the client page (swap icon), the Clients list selection (swap icon) or the edit screen's Sales executive field — all go through `ClientsRepository.transfer`. GM / sales manager: any client to any active exec or Unassigned; KAM: only clients of their team, to their team (app-side, `features/clients/transfer.dart`, unit tested; rules unchanged). A transfer appends {fromId, toId, byId, at} to `clients.transfers` (shown as "Transfer history" on the client page), deletes the previous owner's not-done plan items for those clients dated today or later (past plans and visits stay), and notifies both people (`clientsTransferredIn` / `clientsTransferredOut`, where `ownerId` = the other exec).

## Data model
- Firestore `users/{uid}`: name, email, phone, role, kamId, active, odooName, monthlyTarget
- `clients/{id}`: contactPerson, email, notes, legalName, street, state, country, receivable, payable, currency, contacts[], createdBy (manual), vat, nameKey, name, aliases, phone, mobile, address, city, tags, odooSalesperson, googlePin, lat, lng, assignedTo, category, lastVisitAt, createdAt, updatedAt, source ('import'|'manual'), importBatchId, hidden, hiddenBy, hiddenAt, transfers[]
- `clients/{id}/attachments/{id}` and `visits/{id}/attachments/{id}`: storagePath, url, fileName, contentType, size, uploadedBy, createdAt (files in Storage `{clients|visits}/{id}/{ts}_{name}`, `lib/features/attachments/`)
- `users/{uid}/devices/{fcmToken}`: platform, lang, updatedAt (push tokens, `features/notifications/push.dart`)
- `visits/{id}`: clientId, clientName, salesExecId (visitor: exec or KAM), checkedInAt, checkInLat/Lng, accuracy, mocked, distanceMeters, notes, status, kamId?, kamMarkedAt?
- `visits/{id}/comments/{id}`: authorId, body, createdAt
- `tasks/{id}`: ownerId, date ('yyyy-MM-dd'), month, clientId?, clientName?, title, createdBy, approval (pending|approved|rejected), approvedBy, done, doneAt, visitId
- `notifications/{id}`: toId, fromId, type (planSubmitted|planApproved|planRejected|planChanged|clientsTransferredIn|clientsTransferredOut|trackingIssue), issue?, ownerId, date, count, read, createdAt
- `settings/visitRules`: {A|B|C: {green, yellow}}
- `import_batches/{id}`: fileName, importedBy, added, updated, unchanged, skipped, createdAt
- RTDB `live_locations/{uid}`: lat, lng, accuracy, speed, mocked, fixAt, updatedAt (overwritten); `presence/{uid}`: online, lastSeen, gpsOn, permission, batteryOptimized (Android), onDuty (onDisconnect sets offline); `location_history/{uid}/{day}/{push}`: lat, lng, accuracy, mocked, t
